Windows portable build environment (scripts/windows-env.ps1)

Host: Windows x64; Node 24.19.0, npm 11.17.0, Rust 1.99.0 MSVC.
A project-local toolchain was used without changing the system PATH:
  Rustup/Rust: official static.rust-lang.org downloads, SHA-256 checked.
  xwin 0.10.0: official Jake-Shadle/xwin release, SHA-256 checked.
  Microsoft CRT/SDK: xwin winsysroot, MSVC 14.44.17.14 / SDK 10.0.26100.
  Resource compiler: Microsoft.Windows.SDK.BuildTools 10.0.26100.9169.
  clang-cl / llvm-lib: LLVM 21.1.8 official Windows release.
  LLVM download SHA-256:
    7a5386c26497db1691f320121e5b113364dd0274b98e55f15f4dbc00c0450113
  Linker: the lld-link executable supplied by the installed Rust toolchain.
  NSIS 3.11 / nsis_tauri_utils 0.5.3: downloaded and checked by Tauri.

scripts/windows-env.ps1 configures only the current PowerShell process.
The .tools directory is local build tooling and is excluded from the source
archive. A standard Visual Studio C++/SDK installation can build the project
with npm ci followed by npm run desktop:build, without this adapter.

The release build uses the default production identifier org.folio.pdf and
does not enable native-qa or a WebView2 remote-debugging port.

Linux cross-compilation (experimental)

Host: Debian 13 Linux x86_64. Windows target: x86_64-pc-windows-msvc.
Tauri CLI: locked npm dependency. Native dependency graph: src-tauri/Cargo.lock.

docs/windows-build.Dockerfile builds the folio-windows-build image from
rust:slim-bookworm. It installs clang/lld/llvm/NSIS, cargo-xwin and the MSVC
Rust target. BuildKit secret ca_bundle supplies the host's trusted CA bundle:
  docker build --secret id=ca_bundle,src=/path/to/combined-ca.crt \
    -t folio-windows-build -f docs/windows-build.Dockerfile .
scripts/cargo-windows.sh runs cargo xwin in that image with local Docker,
mounting the workspace, its CA bundle and named caches, and accepts the
Microsoft SDK/CRT terms required by cargo-xwin. Review these terms before
using this build route.

From the application root:
  npx tauri build --target x86_64-pc-windows-msvc --no-bundle \
    --runner "$PWD/scripts/cargo-windows.sh"
  npx tauri bundle --target x86_64-pc-windows-msvc --ci

Bundling on Linux uses NSIS from the image, Tauri's downloaded
nsis_tauri_utils DLL and Win/RestartManager.nsh from upstream NSIS, supplied in
docs/nsis/RestartManager.nsh because Debian's NSIS 3.08 does not include it.
Tauri marks cross-platform bundling as experimental. This route verifies
compilation and packaging, not Windows startup, dialogs, file associations,
installation or SmartScreen acceptance; a normal Windows build uses Tauri's
Windows bundling tools.
