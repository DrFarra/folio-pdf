# How Folio fits together

For finding a symbol, use `graphify query/path/explain` or `graphify-out/wiki/index.md`.
This page holds what the graph cannot show: the paths a document takes and the
rules that break things when ignored. Read the files named before changing them.

## Layers

| Layer | Where | Role |
|---|---|---|
| UI (React) | `src/App.tsx` (the shell), `src/app/use-folio.tsx` (state and coordination), `src/app/*` (its modules, below), `src/components/shell/*` (the view's parts), `src/components/*` | Tools live in `Workbench.tsx`. |

## App's parts

`App()` is the shell: it calls `useFolio()` (`src/app/use-folio.tsx`), which holds the open documents' state and wires the modules below, and shares the result through `FolioContext` (`folio-context.ts`) with the view's parts in `src/components/shell` (`AppHeader`, `AppWorkspace`, `AppOverlays`, and `parts.tsx`: the page stack, the library, the tool section, the Drive indicator, the annotation tool's options). `useFolio` returns state and actions only; the view draws them. A tab's view (page, zoom, mode, tool, panels, search) is shown by one function, `applyView`, whether a tab is switched to or a document opens; `showNoDocument` empties the reader. Each concern it delegates is self-contained:

## A document's life

1. **Open**: `DocumentOpener` (`src/app/opener.ts`) opens what `readDocument` (`src/app/document-reader.ts`) reads and parses, and `openedDocument` (`src/app/opened-document.ts`) restores its session. Native files are read by token (on Windows in one go through shared memory, `read_document_shared`; elsewhere `read_document` / `read_document_range` in chunks, four in flight); a native draft is looked for before the original, which is then not read at all. A file's id is the SHA-256 of its bytes; a library entry keeps it with the file's size and modification time (`KnownFile`, a draft beside it in `drafts/<id>.json`), so an unchanged book is not hashed again; iOS PDFs over 32 MB stay file-backed in PDFKit (`openNativePdf`, `isNativePdfDocument`) and most tools refuse them. Bytes are lent to the engine (`inspectOwnedPdf`) so a big book is held twice, not three times. `inspectDocument` removes the annotations Folio draws itself (highlight, note, ink, its own shapes) from the PDF.js copy.
2. **Read**: `pageStack` renders `PDFPage` per page, keyed by page number; a new revision swaps pixels in place.
3. **Annotate**: annotations live in React state (`commitAnnotations`, `UndoHistory`) and the session (`storage.ts`); written into the PDF only on save/export (`exportAnnotated` → `writeAnnotations`).
4. **Edit content**: `DocumentChanges.apply` → `exportAnnotated` (skipped when unchanged, `bytesAnnotations`) → `processPdf` → `openDocument(output, { preserveHistory, quiet })` → undo snapshot. `quiet` keeps scroll and hides the loading screen. Desktop Editar instead changes a live document (`LiveEdit` in `src/app/live-edit.ts` around `editStore.session`, see `docs/editar-en-memoria.md`): `session.edit` → the page's version goes up and `PDFPage` draws it from the session; `LiveEdit.write` makes the written PDF the document's bytes after a pause (four times as long as the last write took, at least 0.8 s: a change made while it writes waits, «Guardando el cambio…»); leaving Editar reopens the reader once and parks the live document (`LiveEdit.park`, up to `PARK_LIMIT`), so its steps still undo one by one; switching documents closes it (`LiveEdit.close`) and folds its steps into one.
5. **Draft**: every modified revision is stored as a draft (`Persistence.draft`, IndexedDB on web, Rust store natively) and recovered on reopen.
6. **Save**: `DocumentOutput.save` → `savePdf` / `saveOriginalPdf` / Drive. Native writes need an output token from `choose_output`/`choose_export`/`choose_folder` and go through `write_*` (`atomic_write`, `protect_original`).

## Rules that bite

- Engine memory: MuPDF WASM caps near 1.8 GB and saves to an in-heap buffer; PDFs over ~0.75 GB cannot be saved modified (`save()` gives a Spanish error). Open PDFs ≥ 32 MB are streamed, not copied.
- Workers: one request each; a worker that errored or handled > 32 MB is discarded (`client.ts`). Long jobs keep alive by posting progress (`split` parts).
- Content edits are redaction + redraw (`redactPage`, `appendDrawing`), always followed by `verifyRetainedGlyphs`; failures never return a partial PDF. `appendDrawing` must not re-wrap q/Q per edit.
- Moved text is re-emitted one glyph per text object (`glyphDrawing`): as one run, MuPDF's writer rounds glyph places to whole thousandths of an em and long lines drift. Its ToUnicode is rebuilt from the glyphs' own characters (`mapCharacters`), since the writer's, taken from a subset font's cmap, can misname glyphs (Segoe UI's «(»).
- Page item ids (`text-paragraph-b3`, `image-2`) are positional: valid only for the revision they were read from (in Editar, for the page's live version: `EditStore.key`).
- A selection in Editar can hold several items of one page (`Selection.others`); their changes go to the live document as one batch (`editDocumentAll`), each item found again by kind and place because earlier changes renumber the page.
- Editar's live document undoes with MuPDF's journal. Saving it with `garbage>=2` silently breaks the journal: it is written with `garbage=1`. Anything that reads `doc.bytes` during Editar must `liveEdit.write()` first (save, tab switch and close, quitting do).
- Shapes are Folio annotations (Square/Circle/Line), editable only when created by Folio (`NM` starts with `Folio:`).
- The PDF's own drawings (boxes, rules) are read from the page's content streams (`pageDrawings`) and edited by rewriting their operators in place (`editDrawing`), so stacking order is kept; paths inside Form XObjects are not listed. Ids `graphic-N` are positional like the others.
- Editar's saves use `QUICK` (no object deduplication): deduplicating a PDF with thousands of objects takes seconds per edit.
- Images Folio placed are a Form each, drawn by its own `q … cm /FolioN Do Q` stream (`folioImages`): moving, resizing, turning or removing one rewrites that stream, with no redaction.
- Text Folio wrote (moved, added, retyped) is a Form too, tagged with the box and text it covers (`FolioBox`, `FolioText`; `folioTexts`). It stays editable whatever overlaps it, is offered alone (`text-folio-N`) when the page reads it as part of a neighbour's paragraph, and is moved, copied, removed or retyped by rewriting its wrapper (`rewrap`), with no redaction.
- While an edit is written, the item's old place shows `page-plate` (MuPDF's drawing of that area without the item, requested on hover and when it is selected; kept past the change until the page has drawn it, or the old item shows through) and the result is swapped in only once the page has drawn it (`drawn` in `EditLayer`). The page's items are read only after it is drawn: the live document answers in order. `scripts/tests/edit-image-perf.mjs` measures moving placed images (ghost frames, longest frame), in the browser or a QA desktop build.
- What moves on screen is the item's sprite (`itemSprite`: the item alone on transparent pixels, drawn by the live document with what moving it writes), prefetched on hover; the page's own pixels (`Snapshot`) only until it arrives.
- Binary IPC: Android sends base64 in 2 MiB slices; the bridge cap is 128 MiB (`binary_ipc.rs`). Windows writes a PDF over 4 MiB into a WebView2 shared buffer (`upload_shared`, `upload_shared_end`), in 4 MiB slices: WebView2 hands Folio a request's body only as fast as its main process lets go of it, on the window's thread, so large requests (even in 4 MiB slices) held the window for seconds until the WebView closed, and Editar writes its draft after every pause. Reading back goes the other way on Windows: Folio reads the file into a shared buffer and posts it read-only (`read_document_shared`, `{folioDownload}`; the page copies it and calls `release_shared`), since 4 MiB commands pass through the WebView at ~80 MB/s; elsewhere, and with a WebView2 too old to share memory, 4 MiB ranges (`read_document_range`). Measure with `scripts/tests/open-perf.mjs`: a page drawing its frames does not mean the window answers.
- Layout: `useDeviceLayout` — web is desktop unless a narrow coarse pointer; tablet needs an Android/iPad UA. The desktop app is always desktop.
- OCR (`src/ocr.ts`): each page is rendered, straightened (`src/straighten.ts`: a tilt turns the content without re-encoding it; curved lines flatten into a new page image) and read by Folio's engine. The engine is PP-OCRv5 in ONNX Runtime Web (`src/ppocr.ts`; workers in `ppocr-client.ts`, `ppocr.worker.ts`; models in `public/ocr/ppocr`). It runs on one worker with WebGPU, or on up to 4 CPU workers (WASM threads would need cross-origin isolation, which Folio does not have). tesseract.js only takes over when the engine cannot start. WebGPU sessions must be created one at a time. `docs/ocr-benchmark.md` has the numbers.
- OCR can also rebuild a scan as real text (`outcome: 'edit'`). `src/rebuild.ts` keeps a word in the image (searchable) when it is not in the Spanish/English word list (`public/ocr/words.bin`, built by `scripts/build-wordlist.py` from the RLA-ES and SCOWL spelling dictionaries and wordfreq's large lists, which hold a textbook's terms; a word in capitals counts with an accent put back, and a word broken at a line's end with the start of the next) and was read with any doubt, or bears the marks of a misreading or of a sub/superscript; it keeps a line in the image (searchable) when it was read with doubt (score < 0.85, or < 0.97 for a line with no paragraph around it, such as a figure's label), is a short label, has a background that is not plain (figures, photos) or a width that does not fit its text. Otherwise it reads the line's ink and background colours (either polarity; a line on a band of its own colour, a table's dark row, takes the band as background) and erases its letters with their halo and the paler ringing of compression, filling each pixel from the nearest clear background in its row and column, read per column so a line over two colours keeps both. Long thin rules and fills stay; strokes where boxes of close lines overlap stay with the line they belong to. `cleanPaper` keeps pale coloured cells and flattens areas printed in one colour. The engine's `ocr` operation replaces the page with that image and writes each line as Folio text (`writeLine`). Each word is written at its own place and width. The face is chosen by `pageFaces` among Helvetica, Times and the open fonts in `public/fonts/ocr` (`faces.json`; Palatino-, Century-, Bookman-, Garamond-, Cambria-, Calibri-like, a humanist and a geometric sans, a slab). Each word is drawn over the original scan, softened like the scan and correlated with its ink in shades (a binary overlap only measures how thick the ink is). Sizes come from the words' widths, not the box heights, and one face keeps one size and one width across the page; the baseline comes from the band of small letters in the ink, since a box can reach into the next line. Serif or sans is decided first, for the page, then for each paragraph from its stroke contrast (upright stems against horizontal strokes: about 2 in serif faces, under 1.5 in sans, which the shape fit cannot tell at small sizes) and the family that fits all its lines; a closer family only when it fits clearly better than Times or Helvetica. Lines of one size, colour and weight share a face. A style is bold when it differs from the body (size, colour, or a line or two) and the bold face fits clearly better; a word within a line is bold only in a run of two or more heavier words that the bold face fits better together. Stroke widths are the ink summed across each stroke at the line's own contrast, which a blur does not change. Letter heights are measured by drawing the letters (MuPDF.js's text bounds are the whole font box). A page keeps one serif and one sans family (a slide one typeface), chosen by how well each fits its ten longest lines, each at the softening that suits it (short cells and fragments, at one page-wide softening, tip close families the wrong way); a face that lays down less ink than the scan is written with an outline in its own colour (text render mode 2, one copy of the text) that brings its ink up to the scan's; the faces cover the common book and slide faces with open equivalents (Palatino → Pagella, Gill Sans → Gillius, Minion → Crimson Text, Myriad → Source Sans 3, Rockwell → Rokkitt). Word places come from the ink's own gaps when they part into as many runs as there are words. `cleanPaper` whitens the paper and restores black ink in what stays an image. Only scans are rebuilt (`text-layers`: an image over nearly all the page, little text on top); an earlier OCR's invisible layer goes with the old page. `scripts/tests/ocr-real.mjs file.pdf#page` runs real pages through the whole path and writes before/after images to `test-results/real/`.
- CI builds with `cargo --locked`. The Windows dev PC has rustup (`%USERPROFILE%\.cargo\bin`, not on the shell's PATH by default) and the Visual Studio 2022 C++ build tools, so `cargo check --locked` in `src-tauri` and local Tauri builds work there too.

## Tests

Plain Node + Playwright scripts in `scripts/tests` (`npm run test:<name>`; `npm test` runs all after a build). Engine suites import the engine directly; UI suites serve `dist/` with `vite preview`. Desktop editor: `edit-mode-ui.mjs` (also in WebKit on the Mac build); touch editor suites run as an Android tablet (`ui-helpers.mjs`). Mac packaging requires named evidence files (`scripts/package-macos.py`).
